# ZK workload harness (Paper A experiments)

Real local measurements of EZKL proving cost for the two release workloads.
Nothing here estimates a number: every CSV row is a run that completed on this
machine, or an explicit `status=error` row with the real exception.

## Environment

`ezkl` 23.0.5 ships a `cp37-abi3` wheel that works on this repo's Python 3.15
venv. Extra deps beyond `requirements.txt`:

```bash
.venv/bin/pip install -r zk/requirements-zk.txt
```

Notes that cost time to discover:

- `ezkl.get_srs` is async and must run inside a live event loop
  (`asyncio.run`); calling it directly raises `no running event loop`.
- In EZKL 23.x, `setup` and `gen_witness` take the **compiled circuit** path,
  not the `.onnx` path.
- `gen_settings` rejects a dynamic batch axis (`Undetermined symbol in
  expression: <Sym0>`), so every model is exported with a static batch of 1.
- Proving keys are multi-GB at the sizes we sweep. `zk.runner` deletes
  `pk.key` after verification (it is regenerated by `ezkl.setup`); `vk.key`,
  settings, witness and proof are kept so every row stays auditable.

## Files

| path | role |
|---|---|
| `zk/workloads.py` | model definitions, public data, ONNX export, `FACTORIES` registry |
| `zk/runner.py` | one config: settings → compile → setup → witness → prove → verify |
| `zk/scaling.py` | resumable sweep; one subprocess per config; writes `results/zk_scaling.csv` |
| `zk/quant_utility.py` | float vs fixed-point accuracy; writes `results/zk_quant_utility.csv` |
| `zk/utility.py` | DP-noise accuracy curve at ε ∈ {0.5…8}; writes `results/zk_utility.csv` |
| `zk/incircuit_cost.py` | analytical in-circuit cost model (ESTIMATED, not benchmarks) |

## Workloads

- `mlp_tabular` — 30-64-32-1 MLP, Wisconsin breast-cancer tabular set
  (scikit-learn, 569×30, binary). Width-scaled variants `mlp_h128 … mlp_h1024`.
- `tiny_cnn` — 2 conv + 2 FC on CIFAR-10 downsampled to 16×16 (10 classes).
  Channel-scaled variants `cnn_c4_8_fc32 … cnn_c16_32_fc128`.

Data: CIFAR-10 is expected at `zk/data/cifar-10-batches-py` (the tarball is in
`zk/data/cifar-10-python.tar.gz`); the tabular set ships with scikit-learn.

## Run

```bash
.venv/bin/python -m zk.scaling --check        # what is done / missing
.venv/bin/python -m zk.scaling                # fill the grid, stop once >= 50k rows
.venv/bin/python -m zk.scaling --all          # whole grid
.venv/bin/python -m zk.scaling --configs mlp_h512 cnn_c8_16_fc64
.venv/bin/python -m zk.quant_utility
.venv/bin/python -m zk.utility
```

The sweep is resumable: the CSV is the resume state, and a second concurrent
sweep is refused by an `flock` on `results/.zk_scaling.lock`.

## Columns in `results/zk_scaling.csv`

`num_rows` is the EZKL constraint-row count for the circuit (`logrows` is the
next power of two the SRS must cover). `prove_s`, `verify_ms`, `setup_s` and
`witness_s` are wall-clock. `peak_rss_mb` is `ru_maxrss` of the subprocess that
ran that config alone. `scale_bits` records the fixed-point width that produced
a verifiable proof; `attempts` > 1 means the default calibration overflowed the
range-check domain and a wider scale was used (see `error` for the failed
attempt's trace).

## Honesty boundaries

- One machine (Apple silicon laptop), one run per config, no repeated trials.
- The circuit proves the quantized forward pass and the public binding. It does
  not prove that the discrete Gaussian sampler ran; sampling and the RDP update
  are modelled analytically in `zk/incircuit_cost.py` and marked ESTIMATED.
- Comparisons against deployed systems (e.g. Drynx) are cited, never measured
  here.
